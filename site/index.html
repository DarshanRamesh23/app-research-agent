100-app API research agent

An AI agent researched 100 apps (auth, access, API surface, MCP, buildability) with evidence URLs. Accuracy was checked against a human-checked gold set.

Headline patterns

  • 22 of 100 apps are buildable today; 17 more with a caveat; 1 blocked; 53 unknown; 7 not resolved by the agent.
  • Most common auth: oauth2 (37), unknown (31), api_key (26).
  • Most common blockers: paid_plan (6), ship_path_unverified (5), app_review (2).
  • 8 apps are free to test but gated to ship publicly (two-layer gate): Zendesk, Intercom, LiveAgent, Vonage, DataForSEO, SE Ranking.
  • Official MCP found for 26 apps (community 1). 'No' means 'not found', not proven absent.

How the agent works

apps.csv → discover (official docs, pricing, partner pages) → fetch + cache 3-5 pages → extract to a fixed enum schema with a verbatim quote per claim (no quote = unknown) → L1 code checks (enums, quote must appear on the page) → L2 independent verifier call (supported / unverifiable / contradicted, then re-research) → rules (CLI-only apps have no API access) → this page. Pass 1 is frozen so improvement can be measured.

Where a human was needed: seed URLs for apps the agent could not find docs for; the gold set (12 apps, filled from vendor docs and corrected, every change logged); resolving thin or gated apps. 7 apps got no record from the agent and are shown as no_data, not guessed. L2 ran on a mixed Gemini model chain because of daily quota limits.

Proof and how to run
